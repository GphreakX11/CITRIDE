# Implementation design

Retain existing React/FastAPI/RDF persistence/auth/hosting. The generator owns the eight deterministic array exports and a conn compatibility view; seeds no network content from the retired capture. Typed gateway identities use existing canonical IDT assignments. Existing dependency/effect assumptions are unchanged.

`zeek_logs.load_zeek_json` is the single lossless disk reader for simulated and future real exports. API wraps logs in the existing telemetry-stream response shape and omits duplicate compatibility network view. `zeek_validation` applies strict simulated-only schema, documentation-address, reserved-name and provenance checks without restricting real imports. Security tests alone contain the retired narrative denylist. New reference resolution checks cover primary and supplemental evidence.

A reusable A3 component consumes actual bootstrap events and telemetry streams for timeline/raw/hunts. It does not manufacture entity mapping or simulation provenance for real exports. Standard fields precede CITRIDE extensions; linked records are explicitly highlighted and remain reachable. Export preserves complete raw streams as JSONL. Shared-source hunt distinguishes completed vendor VPN access at A from B/C probes.

Retire report/capture modules, routes, cases and UI wiring. Already persisted retired reference cases are hidden/unsupported, not rewritten into Watershed evidence and never allowed to poison normal-case lists. All new-case consequence logic remains based on existing authored scenarios, not network activity alone.

Final gates: deterministic check; all backend tests (real disposable PostgreSQL when available); frontend tests/format/build; repository denylist; preserved IDT/map regression checks; actual isolated-reset API and desktop/mobile browser evidence including raw download readback.
