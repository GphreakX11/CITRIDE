## Backend record service (parent-callable exact API)
`RecordsService(store, scripted=None, reference=None, scenario=None, now=None)` in `citride.records`; defaults load source files beside scenario_path, falling back packaged data. Expose `load_inputs(scenario_path)` if useful; validation against the supplied generated seed, not today's historical baseline. `now` is an injectable aware UTC datetime callback.
- `.seed(dataset)` initializes nine collections, meta/clock from supplied configuration **without saving**; called from Repository._seed_dataset for atomic initial/reset behavior. Seed uses the same ingestion primitive as future callers.
- `.initialize()` locks/loads, seeds only if records meta absent, saves once if changed; preserves ordinary existing baseline/runs/cases.
- `.on_case_opened(dataset, case_record)` links a linkedEventId case to its scripted display ID and attaches relative offsets at captured case-open story time; no save. Never mutate supplied files or case's immutable event/context/run.
- `.apply_action(dataset, case_record, request, who='Authenticated operator') -> str` validates, mutates only permitted case-scoped records, appends origin-preserving who/when/what history through ingestion, returns case activity message, **no save**. CommandService persists record changes + case version/receipt atomically in its existing save. No locking recursion inside these dataset methods.
- `.records(incident_id=None) -> dict` read-only snapshot with top-level nine collections, `storyNow`, `timing`, `taskGroups`, all supplied label maps plus derived status-label maps for task/team/asset statuses. `statewideIncidents` exposes four unrelated incidents until linked case, then fifth has caseId/live status/live reviews/progress. No duplicated scripted Watershed case. Query may be case UUID or supplied display ID; case scope excludes other-case records. `storyNow` advances real time from incidentOrigin + 1h since seed/reset. Offset records immediately available on opening, with derived timestamps relative to opening; do not silently drop authored future-offset statuses. Compute late at read time, never persist status=late. Read snapshot may enrich derived fields such as at, dueAt, etaAt, late.
- `.story_now()` -> aware ISO string (health field).
- `.ingest_records(records, origin)` public durable method, routed to same dataset primitive used by seed and actions; preserve per-record origin/history, validate refs, no automatic side effects beyond this store.
- module exports `ACTION_FIELDS` (action->set of required flat payload fields) and `validate_action(request)` raising InvalidModelError; parent merges fields into existing strict command request validation.

Nine collection names: statewideIncidents,teams,responseTasks,contacts,assessments,assetStatuses,hunts,decisions,partnerProducts. Input `incidents`->statewideIncidents and `tasks`->responseTasks. Sources,taskGroups,label maps,timing are configuration, not separate mutable records. Task teamId may resolve to a supplied taskGroup (`utilities`/`watch-floor`) as well as a deployment. Supplied reference items omit record-level origin/classification/handling; these are configuration, preserve raw file exactly, validate configured sources/refs and inherit source provenance when instantiated, rather than reject the provided authoritative file or invent replacement values.

## Canonical flat record action payloads
Existing expectedVersion/clientRequestId stay parent-owned and mandatory. Same existing actions endpoint, same same-request replay/conflict/closed-state rules.
- record_assessment: subject,cluster,actorLabel,confidence,note (update attribution for current case; medium is supplied legal confidence).
- set_asset_status: entityId,status,note (note becomes record detail).
- record_hunt: huntId,status,resultNote (keep original query).
- set_contact_status: contactId,status,note.
- record_decision: optionId,decision,decidedBy,note (decidedBy is supplied role note, not authority verification).
- set_team_status: teamId,status,people,locationLabel,updateText (people={onSite,remote,traveling,standby} nonnegative integer counts).
- add_task: label,teamId,ownerRole,dueAt (aware ISO timestamp).
- set_task_status: taskId,status.
History and Activity assert recorded tracking only, never actually dispatch/send/contain. Auth principal not available by name in existing single-owner shared-password app; history truthfully records Authenticated operator plus optional declared decision role, not invented personal identity.
